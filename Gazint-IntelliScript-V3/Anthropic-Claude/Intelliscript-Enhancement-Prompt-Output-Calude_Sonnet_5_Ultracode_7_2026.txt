## Summary

I dug into why this doesn't get recognized in some laptop BIOS/UEFI screens, and rewrote [Gazint-IntelliScript-V2.ino](Gazint-IntelliScript-V2.ino) in place. Everything below was actually compiled and verified with `arduino-cli` (installed AVR core + all libraries fresh, no prior toolchain existed on this machine) — not asserted from memory.

### Root cause of the BIOS-detection issue (verified against the HID report structs, not guessed)
The stock `Keyboard`/`Mouse` libraries on the ATmega32u4 publish keyboard+mouse as **one combined HID interface using Report IDs**. Many BIOS/UEFI setup screens only implement the plain USB HID **Boot Protocol** — a fixed 8-byte report with no report ID — and silently ignore anything else. That mismatch is the standard explanation for "shows up fine in Windows, invisible in BIOS on some machines." Fix: switched to **HID-Project's `BootKeyboard`/`BootMouse`**, which I confirmed (by reading the library source) implement exactly that 8-byte boot-protocol report. This is a hypothesis grounded in well-documented HID behavior, not something I could confirm on your actual Dell hardware — flag it as `ASSUMED root cause`, and worth confirming on one of the affected laptop models.

### What else changed, and why
- **Buttons**: switched to `INPUT_PULLUP` (button → GND). No external resistors needed, and an unwired/miswired pin now fails safe (reads "not pressed") instead of floating.
- **Real debouncing**: the original code was level-triggered with a `delay(50)`, so holding a button down replayed its *entire* macro (including the admin password) every ~50ms for as long as it was held. Now edge-triggered — fires exactly once per press.
- **Found and fixed a real bug via compilation**: `Mouse.move()`/`BootMouse.move()` take a `signed char` (-128..127). The original passed ±200, which silently overflows (-200 wraps to +56) — the mouse "jiggle" was moving the wrong distance/direction the whole time.
- **Fixed `"D:\Dell BIOS"` → `"D:\\Dell BIOS"`** (unescaped backslash).
- **Efficiency**: the idle screen was redrawn (full I2C frame push) twice per loop, forever, at ~20Hz. Now it only redraws when the screen actually changes.
- **Added a 4th button** (pin 9) for a disk-wipe helper: Shift+F10 → `diskpart` → `list disk`, then **stops** — it deliberately never runs `select disk`/`clean` itself, so it can't wipe the wrong drive if disk numbering ever differs. This directly targets your stated need for techs who reformat drives before installing Windows.
- Dropped the unused `#include <SPI.h>` (I2C-only display).
- One thing I checked and was **wrong** about initially: I assumed the old single-argument `Adafruit_SSD1306(OLED_RESET)` constructor was removed from the current library. It isn't — v2.5.9 still ships it with a hardcoded 128×32 compatibility default. I corrected that comment in the file rather than leave a false claim in there. I still switched to the explicit constructor since that fallback is an internal default of this one library version, not a guaranteed contract.

### USB-C (hardware, not firmware)
The ATmega32u4 only speaks USB 2.0 Full-Speed — electrically fine over USB-C, but only through a cable/adapter with correct CC-line termination (5.1kΩ Rd). Cheap "charge-only" adapters omit this and won't enumerate as a data device on *either* port type. Use a certified USB-A↔USB-C data adapter, or a Pro Micro variant with a native USB-C receptacle (same MCU/USB stack — no firmware changes needed).
